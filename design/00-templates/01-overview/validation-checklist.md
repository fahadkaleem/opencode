# Stage 1: Overview - Validation Checklist

Use this checklist to verify the Overview document is complete before proceeding to Stage 2 (Requirements).

---

## Completeness Checks

### Problem Statement

- [ ] Problem is clearly articulated (not vague)
- [ ] Specific personas affected are identified
- [ ] Concrete example/scenario is provided
- [ ] Business impact (pain) is quantified where possible
- [ ] Urgency/timing rationale is explained

### Vision

- [ ] Vision statement describes desired end state
- [ ] Vision focuses on outcomes, not features
- [ ] Vision is inspirational but achievable
- [ ] "What this is NOT" is explicitly stated

### Business Goals

- [ ] Each goal has a unique ID (BG-XXX)
- [ ] Goals are strategic (not features)
- [ ] Business impact is explained for each goal
- [ ] At least 2-3 primary goals defined

### Success Metrics

- [ ] Each metric has a unique ID (SM-XXX)
- [ ] Metrics are specific and measurable
- [ ] Current baseline is documented (or noted as unknown)
- [ ] Target values are quantified
- [ ] Measurement method is defined
- [ ] At least 2-3 key metrics defined

### Scope

- [ ] In-scope items are explicitly listed
- [ ] Out-of-scope items are explicitly listed with reasons
- [ ] Assumptions are documented with impact analysis
- [ ] No ambiguity about what's included/excluded

### Constraints

- [ ] Business constraints documented
- [ ] Regulatory/compliance constraints documented (if applicable)
- [ ] Organizational constraints documented
- [ ] Each constraint has rationale

### Stakeholders

- [ ] Key stakeholders are identified
- [ ] Target users are identified
- [ ] Engagement level specified for stakeholders

### Dependencies & Risks

- [ ] External dependencies identified with owners
- [ ] Key business risks identified
- [ ] Risk likelihood and impact assessed
- [ ] Mitigation strategies noted

### Timeline

- [ ] High-level milestones defined
- [ ] Timing is realistic given constraints

---

## Quality Checks

### Clarity

- [ ] Document can be understood by non-technical stakeholders
- [ ] No unexplained jargon or acronyms
- [ ] Glossary includes all domain-specific terms

### Consistency

- [ ] Goals align with problem statement
- [ ] Success metrics align with goals
- [ ] Scope aligns with vision

### Completeness

- [ ] Executive summary captures essence of document
- [ ] All template sections are filled in
- [ ] No "[TBD]" or placeholder text remains
- [ ] Document history is updated

### Traceability

- [ ] All IDs follow naming conventions (BG-XXX, SM-XXX, etc.)
- [ ] Goals are referenceable from Requirements stage

---

## Approval Criteria

Before marking this stage complete:

1. **Author Review**: Author has reviewed all sections
2. **Stakeholder Review**: Key stakeholders have reviewed and provided feedback
3. **Sign-off**: Document owner has approved
4. **Version Control**: Document is committed to version control

---

## Common Issues to Watch For

| Issue                          | How to Fix                                    |
| ------------------------------ | --------------------------------------------- |
| Vague problem statement        | Add specific numbers, examples, scenarios     |
| Features masquerading as goals | Reframe as business outcomes                  |
| Missing out-of-scope items     | Ask "what might someone assume is included?"  |
| Unmeasurable success metrics   | Add specific targets and measurement methods  |
| Missing constraints            | Consider budget, time, compliance, technology |
| No user identification         | Add target user types and their goals         |

---

## Ready for Stage 2?

Answer these questions:

1. Can you explain the product vision to a non-technical stakeholder in 5 minutes?
   - [ ] Yes
   - [ ] No → Simplify and clarify

2. Is it clear what success looks like and how we'll measure it?
   - [ ] Yes
   - [ ] No → Add/refine success metrics

3. Is scope unambiguous (no gray areas)?
   - [ ] Yes
   - [ ] No → Clarify in-scope and out-of-scope lists

4. Are all key stakeholders identified?
   - [ ] Yes
   - [ ] No → Add missing stakeholders

**If all checks pass → Proceed to Stage 2: Requirements**
